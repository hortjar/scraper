# Frontend Conventions

Vite 8 · React 19 · TypeScript · TanStack Query 5 · TanStack Store · TanStack Router ·
shadcn/ui · Tailwind 4 · i18next · Hey API generated client.

Read alongside [15-DESIGN-SYSTEM](./15-DESIGN-SYSTEM.md) (how it looks) and
[16-I18N](./16-I18N.md) (how it speaks).

## 1. Deltas from REACT.md

[docs/REACT.md](./REACT.md) remains the house React guide for component style,
testing, code splitting, and build config. Where this project differs:

| REACT.md says | We use | Why |
|---|---|---|
| Zustand | **TanStack Store** | Project requirement. Same model; `useStore(store, selector)`. |
| Ant Design / MUI | **shadcn/ui + Tailwind** | Project requirement. Components are owned, not imported. |
| Axios + interceptors | **Hey API generated client** | The client is generated from the API's OpenAPI document — zero hand-written request code, and it can't drift. Interceptor duties (auth, error normalization, 401 refresh) live in one configured client instance. |
| React Router v6 | **TanStack Router** | ⚠️ *Flagged deviation.* Typed routes and typed **search params** — every filter, range, and selection lives in the URL instead of in a store. |
| `tests/` top-level | **Colocated `*.test.tsx`** | Matches the backend. `tests/e2e/` still holds Playwright specs. |
| — | **No `useEffect`** (§4) | Added rule, stricter than REACT.md. |
| — | **No literal strings** (§7) | Added rule. Everything goes through i18n. |

## 3. Component rules — atomic, small, one job

| Layer | Owns | Must not |
|---|---|---|
| **Atoms** (`components/ui`) | One element's look and behavior | Know about the app, fetch, or read stores |
| **Molecules** | 2–5 atoms doing one recognizable job | Fetch data, own more than trivial local state |
| **Organisms** | Composed sections; may own interaction state | Fetch data directly |
| **Containers** (`features/*/containers`) | Fetching, mutation wiring, prop assembly | Contain layout beyond composition, or format values |
| **Layouts** | Page skeleton, slots | Know which feature is inside them |
| **Routes** | URL, params, loaders, one container | Anything else |

Hard limits, enforced by lint where possible and by review otherwise:

- **≤ 150 lines** per component file. Over that, it's doing more than one thing.
- **≤ 7 props.** More means a missing sub-component or a props object.
- **A component either fetches or renders — never both.** Container/presentational
  split is not optional here; it's what makes presentational components testable
  without MSW and reusable in the landing page.
- **No god components.** `MonitorEditor` is a route composing `MonitorBasicsForm`,
  `ExtractorList`, `SchedulePicker`, `RulesBuilder`, `PreviewPanel` — five files,
  each independently testable, none aware of the others.
- **No prop drilling past two levels.** Use composition (`children`, slots) first;
  context only for genuinely ambient values (theme, locale, current user).
- **Props are data, not instructions.** `<StatusPill status="failing" />`, not
  `<StatusPill color="red" icon="x" label="Failing" />`.

## 4. Never use `useEffect`

> **`useEffect` is banned in feature code.** `react-hooks/exhaustive-deps` won't
> save you from the real problem: effects turn a declarative tree into an imperative
> sequence of re-renders, and every hard bug in a dashboard like this one — double
> fetches, stale closures, flashing states, loops — comes from that.

What to use instead:

| You want to… | Use |
|---|---|
| Fetch data | `useQuery` / route `loader` — never an effect |
| Refetch on an interval | `refetchInterval` |
| Derive state from props/state | Compute during render. It's cheap; memo only if profiled |
| Reset state when a prop changes | `key={id}` on the component |
| React to a user action | The event handler |
| Tell a parent something changed | Call the callback in the handler |
| Expensive initial state | `useState(() => compute())` |
| Read an external store | `useStore(store, selector)` / `useSyncExternalStore` |
| Sync to the URL | Router search params |
| Animate | CSS transitions, View Transitions API |
| Focus, scroll, measure | `ref` callback, or a blessed primitive |

**The escape hatch:** `src/lib/browser/` contains a small, reviewed, tested set of
primitives that *are* allowed to hold effects, because they wrap a genuine external
system: `useMediaQuery`, `useOnlineStatus`, `useInterval`, `useEventListener`,
`useDocumentTitle`, `useHotkey`. Feature code imports these. Adding a new one
requires justification in the PR and a test.

ESLint enforces it: `no-restricted-syntax` blocks `useEffect`/`useLayoutEffect`
outside `src/lib/browser/**`. Bypassing it needs an inline disable with a comment
explaining which external system is being synchronized — and that's a review conversation.

## 5. API layer — generated, not written

The backend publishes OpenAPI 3.1; **Hey API** generates the client and the
TanStack Query options.

```ts
// openapi-ts.config.ts
export default {
  input: 'http://localhost:3001/docs/json',      // or the committed openapi.json
  output: 'apps/web/src/api/generated',
  plugins: [
    '@hey-api/client-fetch',
    '@hey-api/typescript',
    { name: '@tanstack/react-query', queryOptions: true, mutationOptions: true },
  ],
}
```

```ts
// features/monitors/api.ts — thin wrappers, not re-implementations
import { listMonitorsOptions, createMonitorMutation } from '@/api/generated/@tanstack/react-query.gen'

export const monitorsQuery = (filters: MonitorFilters) => ({
  ...listMonitorsOptions({ query: filters }),
  staleTime: STALE_TIME.list,
})
```

- **`src/api/generated/` is never hand-edited.** `pnpm gen:api` regenerates it; CI
  fails if the working tree is dirty afterwards, so client and server cannot drift.
- Query keys come from the generated options. Invalidation uses the generated key
  factories, not hand-written string arrays.
- One configured client instance in `lib/api/client.ts`: `credentials: 'include'`,
  the single-flight 401 refresh, and the response interceptor that converts an
  error envelope into a typed `ApiError` carrying `code`, `messageKey`, `messageParams`.
- `ApiError` → user copy goes through i18n by `messageKey` (see [16-I18N §3](./16-I18N.md)).

## 6. State — three homes, no overlap

| Kind | Home |
|---|---|
| Server data | TanStack Query |
| Filters, sorting, pagination, selection, open dialog ids | **URL search params** |
| Ephemeral UI (sidebar collapsed, density, theme, diff view mode) | TanStack Store |

```ts
// stores/ui.ts — small, single-concern
export const uiStore = new Store({ sidebarCollapsed: false, density: 'comfortable' as Density })
export const useUi = <T,>(selector: (s: UiState) => T) => useStore(uiStore, selector)
```

- **No store exceeds 7 keys.** A store growing past that is two stores.
- Always read through a selector. Derived values use `Derived`, not `useMemo`.
- **No large state objects in components.** More than three related `useState` calls
  means a `useReducer` with named actions, or state that belongs in the URL.
- Persist only genuine preferences, through one `persist` helper.
- Query config: `staleTime` 30s default, `retry: (n, e) => n < 2 && !isClientError(e)`,
  refetch paused when the tab is hidden. Optimistic updates only for toggles and
  renames — never for creates.

## 7. No literal strings

Every visible string comes from i18next — including `placeholder`, `title`,
`aria-label`, `alt`, toast copy, empty states, and validation messages.
`eslint-plugin-i18next/no-literal-string` enforces it. Formatting (dates, numbers,
relative times, currencies) goes through `lib/format`, never `toFixed` or
`toLocaleString` inline. See [16-I18N](./16-I18N.md).

## 8. Version & connection status

The app always shows what it is and whether it's talking to the server. Both live
in the sidebar footer (console) and the page footer (landing).

```
  ● Connected            ← green dot, "Connected" / amber "Reconnecting" / red "Offline"
  v1.4.2 · a3f9c21       ← client version · commit, tooltip shows the API's version
```

- **Version**: build-time `__APP_VERSION__` / `__GIT_SHA__` injected by Vite from
  `APP_VERSION`, compared against the API's version from `/health`. **On mismatch,
  a non-blocking banner offers "Reload to update"** — the classic stale-SPA-after-deploy
  problem, solved cheaply.
- **Connection**: derived, not polled by hand — `useOnlineStatus` (browser events)
  combined with the Query client's error/fetching state and a low-frequency
  `/health` query. Three states: connected, reconnecting (retries in flight or
  health degraded), offline. Announced via `aria-live`.
- Both are one molecule each (`AppVersion`, `ConnectionIndicator`), tested in isolation.

## 9. Charts

Number-typed extractors get a sparkline in list rows and a full history chart on
detail pages. Series colors come from the Signal ramp by stable hash — a given
extractor keeps its color across every view. Axes and gridlines use `--border` and
`--text-subtle`, never a series color. Tooltips show value, delta, and timestamp in
the user's locale and timezone.

## 10. Forms

React Hook Form + an Effect Schema resolver over the generated request types, so
client validation and server validation come from one definition. Field-level
`issues` from a 422 map straight onto fields by path. The monitor editor is the
hardest surface — its composition is specified in §3.

## 11. Performance

- Route-level splitting is automatic; additionally lazy-load the diff viewer,
  charts, and the cron editor.
- `manualChunks`: `react`, `tanstack`, `ui`, `charts`, `i18n`.
- Long lists use `@tanstack/react-virtual`.
- Budgets: landing ≤ 120 kB JS gzip and LCP < 1.5s; console initial ≤ 200 kB gzip;
  Lighthouse ≥ 90. Enforced in CI by `size-limit`.

## 12. Testing

- Vitest + RTL; MSW seeded from the generated client's types. No hand-mocked `fetch`.
- Presentational components test without any network — that's the point of the split.
- Every blessed `lib/browser` primitive has a test.
- Lint gates: no `useEffect` outside `lib/browser`, no literal strings, no
  `console.*`, no deep imports across features.
- Playwright E2E: register → create monitor → see a run; threshold rule that must
  *not* fire; session revoke; landing page renders in both locales.
